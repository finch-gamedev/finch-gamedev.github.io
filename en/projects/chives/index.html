chives

A local-first trading workbench for Taiwan stocks: record trades and P&L across brokerage accounts, backtest and validate trading rules on historical data, then practise with paper trading.

Overview

A workbench for individuals who want to study Taiwan stock trading strategies seriously. It doesn’t connect to a broker, place orders, or recommend stocks. Instead it keeps record-keeping, research and practice in one place, and all data stays on your own computer.

The link above is a static demo: the same interface and code as the real app, running entirely on a synthetic “demo market”. No sign-in, and it never contacts an outside service.

Features

  • Multi-account ledger: record trades, cost basis and realised P&L across several brokerage accounts, and reconcile them line by line against broker statements.
  • Historical data: import years of dividend-adjusted daily bars, and keep the exchanges’ official delisting and ex-rights lists to check the data for gaps.
  • Strategy research: backtest a trading rule, then test it in stages (research period, validation period, held-out test) with parameter sensitivity comparisons, so a rule isn’t just fitted to the past.
  • Paper trading: run a researched rule forward on later market data to see how it actually behaves.
  • Beginner guidance: a goal choice on first use, a step-by-step guide, a glossary cheat sheet and a learning centre.

Stack

Built through AI-assisted development with Claude Code: I owned the requirements, feature planning and acceptance review, and the code was mostly written by AI.

  • Python + FastAPI + SQLAlchemy backend with local SQLite; React + TypeScript + Vite frontend
  • 30+ Playwright browser suites, checking every page at desktop and mobile widths
  • The demo is built by running the real backend on a synthetic market, recording every response, and assembling a server-free static site; an automated scan checks that no real account, token or personal data is included before publishing
  • Double-click launcher and one-click in-app updates

Notes

I built this to find out whether a trading idea actually works, rather than going on gut feeling. The hardest part was not fooling myself: a backtest can easily just fit the past, so the research flow deliberately splits data into research, validation and held-out periods, and parameters can’t be tuned again once they’re frozen.

The other priority was keeping data on my own machine. Ledgers and research results are personal, so the whole tool runs locally; to show it to others, I generate a completely separate demo from synthetic data.
