Care Label Maker

Compose laundry care symbols and text in the browser, auto-arrange them on label sheets, then print or export to PDF.

05/26/2026

Overview

A web tool for small brands and makers to create their own clothing care labels. Pick care symbols, add brand and fabric text, set the label size, and the tool tiles the labels onto A4, Letter, or roll label stock, ready to print or export as PDF. No install, no account; your work is saved in the browser.

Features

  • Full ISO 3758 symbol set: 61 symbols across washing, bleaching, drying, ironing, and professional care.
  • What you see is what prints: the preview, browser printing, and PDF export all render from the same millimetre-based SVG, so on-screen sizes match the printed result.
  • Flexible content: stack and reorder text and symbol blocks freely; when symbols don’t fit, the label grows taller instead of overflowing.
  • Bilingual interface (Traditional Chinese / English).

Stack

Built through AI-assisted development with Claude Code: I owned the requirements, feature planning and acceptance review, and the code was mostly written by AI.

  • React + TypeScript + Vite, fully client-side, deployed on Cloudflare Workers
  • Symbols are generated parametrically from base shapes plus modifiers, giving consistent line weights with no third-party artwork
  • PDF export via svg2pdf.js + jsPDF; state managed with Zustand and persisted to localStorage

Notes

This started with a simple need: a friend runs a clothing shop on Shopee, and every garment needs a care label. The usual options are ordering labels from a supplier or piecing symbols together in a design app, and neither makes sense for a small seller with low volumes. So I set out to build something that works straight from a web page, letting them pick symbols, lay out labels, and print on their own.

Because these labels actually get printed, what mattered most to me was that the screen matches the paper. So from the start, I built the preview, printing, and PDF export on a single SVG source, instead of trying to line up the sizes of each output after the fact. That decision saved a lot of trouble as features were added.
