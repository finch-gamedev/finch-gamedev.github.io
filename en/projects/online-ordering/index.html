Online Ordering System

An online ordering system for small restaurants. Customers order, pick a pickup time and pay online; the owner takes orders, prints tickets and manages the menu and stock from an admin panel, all on free-tier services.

Overview

A pickup and dine-in ordering system for small restaurants. Customers open a web page on their phone to order, choose a pickup time and pay; the owner takes orders, prints tickets and manages the menu and stock from an admin panel. The database and hosting both run on free tiers, so there’s no monthly fee, and a restaurant is already using it in production.

The link above is a demo where you can try the customer ordering flow.

Features

  • Customer ordering: browse the menu by tag, with custom options and add-ons; order for now or book a time slot, with only slots inside business hours offered.
  • Multiple payment methods: cash, LINE Pay and ECPay credit card.
  • Dine-in table ordering: each table gets its own QR code that fills in the table number when scanned.
  • Admin panel: order intake and status tracking, ordering on a customer’s behalf, automatic stock deduction, menu editing with CSV import/export, and sales reports.
  • Printing and notifications: Bluetooth, USB, WiFi and serial receipt printers; new-order alerts via LINE, Discord, Telegram or email.
  • Loyalty points, a bilingual interface (Traditional Chinese / English), and theming with dark mode configurable from the admin panel.

Stack

Built through AI-assisted development with Claude Code: I owned the requirements, feature planning and acceptance review, and the code was mostly written by AI.

  • Next.js (App Router) + React + TypeScript + Tailwind CSS, deployed on Vercel
  • The database can be switched between Google Sheets and Supabase (PostgreSQL); both share a single schema definition and migrate automatically when columns change
  • Payments via LINE Pay and ECPay; image uploads via Cloudinary

Notes

I built this for a friend’s restaurant. The brief was clear: they wanted their own online ordering, without paying a monthly fee for it. So from the first version, running entirely on free tiers was a given. Orders are stored straight in Google Sheets, so the owner can open the spreadsheet to see them, and the site runs on Vercel’s free plan.

As features piled up, I also left room to grow: the data layer is built on one shared schema definition, so when the data outgrows a spreadsheet the restaurant can move to Supabase without rewriting the system.
